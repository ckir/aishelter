Module idempotency 

Source
Expand description

Idempotency middleware.

Replays the stored response when a client retries a mutation with the same Idempotency-Key, so a retry after a timeout cannot execute it twice.

Scope and rules:

  • The key is scoped to the verified principal (the AuthenticatedAgent set by the authentication layer, which therefore must run first) plus METHOD /path. Unauthenticated routes share the anonymous principal. The X-Agent-Id header is never consulted: it is attacker-controlled. The anonymous key namespace is therefore shared by every caller: clients must choose unguessable keys (a random UUID), or a stranger who guesses a key first makes the real caller’s retry a 422.
  • Replaying a key with a different body is a client error (422), not a silent replay of an unrelated response.
  • Only successful (< 400) responses to unsafe methods are stored, so a failed attempt can be retried under the same key. GET/HEAD/OPTIONS pass through untouched.
  • Request and response bodies are bounded; nothing is buffered unbounded.

Known limitation: two concurrent requests with the same new key can both execute, because the key is stored after the handler finishes. Closing that needs a reserve-then-complete protocol.
